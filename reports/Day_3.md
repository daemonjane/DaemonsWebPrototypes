## 1. Overview

Today I focused on building a complete, production‑ready frontend for the TechStore hardware store. The work included establishing a cross‑page design system, implementing dynamic product pages, setting up a structured Git workflow, synchronizing two remote repositories (GitHub and Ositcom), and extending interactivity (cart persistence, quantity picker, expandable product cards). All code is written in vanilla HTML, Tailwind CSS, and JavaScript – no frameworks, ready for future backend integration.

---

## 2. Achievements (Points 1–5)

### Point 1 – Cross‑Page Design System
- Created a **centralized Tailwind CSS configuration** (`tailwind.config.js`) with custom colors (cyan/slate), fonts, animations, and keyframes.
- Built a global `src/input.css` that defines base styles (scrollbar, grid background, hero glow) and reusable component classes (`.btn-primary`, `.glass-header`, `.card-hover`).
- Generated a minified `dist/output.css` that is shared across all HTML pages, eliminating duplicate inline styles and ensuring consistent branding.

### Point 2 – Dynamic Page Implementation
- Developed a **product category page** (`shop.html`) that loads products from a JavaScript array (mock database) and supports:
  - Filtering by category (All, Desktops, Monitors, Peripherals)
  - Real‑time search by product name
  - Sorting by price (low‑to‑high, high‑to‑low) and name (A‑Z)
  - **Expandable product cards** – on hover, each card reveals technical specifications, a quantity selector (+/‑), an “Add to Cart” button, and a “Details →” link.
- Built a **product detail page** (`product‑detail.html`) that reads the product ID from the URL (`?id=...`) and displays full information (image, description, specs, price, and an “Add to Cart” button).
- Added **toast notifications** to give user feedback when items are added to the cart.

### Point 3 – Version Control Strategy
- Documented a **Git Flow** branching model in the project `README.md`:
  - `main` – production‑ready code, tagged releases.
  - `develop` – integration branch for features.
  - `staging` – pre‑release testing.
  - Feature branches created from `develop` and merged via pull requests.
- Defined **commit message convention** (Conventional Commits: `feat:`, `fix:`, `docs:`, etc.).
- Applied the strategy by creating and synchronising all three branches locally and on both remotes.

### Point 4 – Repository Synchronization
- Connected the local repository to two remotes:
  - `origin` – GitHub (`https://github.com/daemonjane/DaemonsWebPrototypes.git`)
  - `ositcom` – Ositcom Git server (`https://git.osinode.com/Ositcom/charbel_elias.git`)
- Synchronised `main`, `develop`, and `staging` branches across both remotes (used forced updates where necessary to resolve unrelated histories).
- Removed stale tags (`v1.0`, `v1.0‑stable`, `v1.1`, `v1.x.x`) and created a clean semantic version tag **`v1.0.0`** for the stable release.
- All branches now point to the same commit (`3e7c338`), ensuring identical state on GitHub and Ositcom.

### Point 5 – Integrated Interactivity (Vanilla JS)
- Implemented a **cart system** using `localStorage` that persists across all pages:
  - Cart items stored as objects with `id`, `name`, `price`, `quantity`.
  - Cart dropdown shows items with quantity controls (+/‑) and a “Remove” button.
  - Total price updates dynamically.
- Added quantity selector directly on product cards in `shop.html` – user can choose how many of a product to add before clicking “Add to Cart”.
- Extended the cart logic to support **in‑cart quantity adjustment** and removal.
- Included a **checkout button** that redirects to a `checkout.html` page (order summary + shipping form – ready for backend integration).
- Maintained a unified header (navigation, search, cart trigger) across all pages, with mobile menu toggle.

## 5. Challenges & Solutions

| Challenge | Solution |
|-----------|----------|
| Multiple remote branches (`develop`, `staging`) had unrelated histories, preventing merges. | Used `git reset --hard main` on `develop` and `staging`, then forced push to align them. |
| Duplicate inline `<style>` blocks on every page caused inconsistency. | Moved all global styles into `src/input.css` and removed inline blocks with a `sed` command. |
| Product cards needed to reveal extra content on hover without breaking layout. | Implemented a CSS transition on `max-height` and `opacity` inside a `.extra-content` div. |
| The header had to be identical across all pages for cart to work. | Copied the exact header from `index.html` into each page and verified IDs (`cart-trigger`, `cart‑dropdown`, etc.). |
